# Keytest for Windows XP

A Zig 0.15.2 / Win32 keyboard canvas. Fills the primary display at its **current resolution**;
the last key stays on screen in white **Noname Sans at ¼ of the screen height**
(192 px at 1024 × 768, 256 px at 1280 × 1024).

| Input | Background |
| --- | --- |
| Consonants (including Y) | Blue `#174ED9` |
| Vowels (A E I O U) | Cyan `#00A0B5` |
| Digits | Red `#D9323B` |
| Punctuation and symbols | Orange `#E67800` |
| Modifiers, Space, navigation, function and control keys | Green `#199843` |

The font is embedded in the EXE, registered privately, and removed on exit.
Speech clips are embedded too, and play through the built-in Windows multimedia
API (`winmm.dll`). No font installation, SDL, .NET, C runtime, or additional
DLL downloads are needed. Audio requires a working XP sound driver.
The initial screen is blank green until a key is pressed. The embedded font
includes the user's custom ampersand glyph.

## Run

Copy `dist/keytest/keytest.exe` to XP and double-click it. The borderless window covers
the primary display, including the taskbar, without changing the resolution or
color depth. The canvas and font adapt when the display resolution changes.
The app reports an error if it cannot use the embedded font.

- **Alt+F4** or **Ctrl+Shift+F12** quits. The desktop display mode is never changed.
- **Esc** displays “Esc”; **Space** displays “Space”. Other controls use readable
  names so missing symbol glyphs never appear as boxes.
- Printable characters follow the active keyboard layout, Shift and Caps Lock.
  Thus `1` is red, while `!` is orange. Latin-1 accented vowels are recognized.
- Long control names shrink proportionally only when needed to fit within 90%
  of the screen width.
- Alt-Tab minimizes the app. Returning to it reapplies fullscreen placement after
  Windows finishes restoring the window, with keyboard focus restored too.
- Windows/Super keys are captured only while Keytest is foreground, to display
  and say “Super”.
  Secure OS sequences such as Ctrl+Alt+Delete remain owned by Windows. Host/VM
  shortcuts can intercept keys before the guest application receives them.

## Spoken keys

- A–Z speak their NATO words: Alfa, Bravo, Charlie, through Zulu. Uppercase and
  lowercase use the same word; the screen still displays the character pressed.
- Digits speak their ordinary names (Zero through Nine).
- Punctuation speaks the typed symbol's name: Shift+7 says "Ampersand", not
  "Seven". All printable ASCII symbols plus common currency/typographic symbols
  have recordings. Unmapped characters say "Unknown character".
- Modifiers and controls say their names, including Control, Shift, Alt, Escape,
  Space, arrows, F1–F24, locks, and supported media keys.
- Each new press replaces the previous voice clip. Holding a key does not keep
  restarting speech. Audio stops when the app loses focus or exits.

The voice is generated by Kokoro, using whole utterances without syllable cuts.
The saved PCM WAVs can be replaced with your recordings for a later build; see
[the voice guide](assets/voice/README.md).

## Build

From the repository root, install the pinned tools and script dependencies:

```sh
mise trust
mise install
mise exec -- just setup
mise exec -- just build keytest
mise exec -- just check
```

See the repository README for mise setup and the macOS 27 SDK workaround
(`just bootstrap-resinator`). The tools run on the development host; XP only
runs the compiled output.

The build uses a Pentium III CPU baseline, Windows XP 5.1 PE headers, and an
explicit startup function. Its audit rejects DLLs or imported APIs outside the
reviewed XP-compatible list and checks embedded icon frames and version metadata.
Builds also create `dist/keytest-xp32.zip` with the executable and documentation.
`just check` verifies formatting, builds the executable, and runs the Zig input
classification and speech-routing tests plus Bun asset, executable-audit, and
packaging tests.

To build a CD image for transfer into UTM on macOS:

```sh
mise exec -- just iso keytest
```

Mount the resulting `dist/keytest.iso` in UTM's virtual CD drive.

## Implementation

`apps/keytest/main.zig` owns fullscreen placement, the responsive font, and buffered GDI drawing.
`shared/win32.zig` declares the minimal 32-bit Windows ABI. `apps/keytest/keys.zig` keeps input
classification separate from the platform layer. `speech.zig` selects embedded
clips using the translated character or control key. The event-driven message loop
does not continuously repaint an unchanged screen.

The font is the user's modified `NonameSans-Web.otf`, exported on September 23,
2026 with an added ampersand. Its internal family name is **Noname Sans Web**,
with a Regular face. The app
requests weight 600, matching the user's WezTerm window-frame configuration.

The icon is embedded in the executable and used by Explorer and the application
window. Its original artwork, XP ICO frames, and generation prompt are in
[assets](assets/ICON.md). No external icon file is required to run Keytest.
